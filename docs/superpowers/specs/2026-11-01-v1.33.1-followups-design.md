# v1.33.1 — finish the v1.33.0 leftovers (short design)

Date: 2026-11-01 · Size: small change · Version: 1.33.0 → 1.33.1

## Intent

v1.33.0 (L3 AI fix) shipped with five known gaps that do not block use.
1.33.1 closes them. No new feature, no behavior change outside these five.

## Goals

1. `kb l3 report` prints the findings of an AI-fixed section, not only a
   `git diff` hint.
2. Missing docling gives a one-line message, not a traceback, in
   `kb l3 lint` and `kb l3 fix apply` (and every other caller).
3. `l3check/fix.py` (704 lines) gets smaller by moving its checks out.
4. A draft may delete a repeated block that holds an image.
5. The guide PDFs in `docs/` match the updated Markdown.

## Non-goals / anti-goals

- No new storage of pre-fix findings; no change to `_l3check.yaml` or
  `_l3fix.yaml` schemas.
- No relaxing of the link check beyond duplicated targets: a link or image
  that appears once must still survive, and order must still match.
- No behavior change in the fix.py split (pure move).

## Findings that shape the design

- `fix._recheck` already drops the old findings of the replaced ids and
  writes fresh detector findings for the new units into `_l3check.yaml`,
  bound to the new digest. `l3_report` hides them because it filters
  `pending` with `s.id not in fix_lines`.
- `parser.load_or_parse` already has a clear message
  (`Docling is not installed. Run: pip install "strata-kb[ingest]"`) but
  raises `RuntimeError`. `KbError` subclasses `RuntimeError`, and the CLI
  turns `KbError` into a clean message.
- Assets are content-addressed (`assets/<sha256>.<png|webp>`,
  `assetstore.py`): byte-identical images share one path. Checked in
  myflix-center-kb: 37 images, none repeated today. `_check_links` compares
  targets only, not alt text, so OCR alt drift does not matter.

## Design per item

1. **Report.** In `cli.l3_report`, after each `[ai-fix]` / `[edited]` line,
   print that section's `_l3check` findings (current digest, unconfirmed)
   with the existing `_l3_finding_lines`. Sections stay counted once.
   *My call:* a finding present before the fix and still present after is
   printed too — "new" means "found on the AI's version", which is what
   `_recheck` stores. The reviewer needs to see what the AI did not fix.
2. **Docling.** `parser.load_or_parse` raises `KbError` instead of
   `RuntimeError`. Same message. Root cause, so lint, fix apply and ingest
   all get it.
3. **Split (approach A, picked).** Move the `_check_*` group and its
   private helpers (`_table_blocks`, `_clip`, `_LINK_TARGET`,
   `_link_targets`, `image_allowed`, ids/heading/prose helpers used only by
   checks — roughly lines 262–435) to `l3check/fixchecks.py`. `fix.py`
   imports them; `fix.image_allowed` stays reachable for `cli.py`
   (re-export or import update). Target: `fix.py` ≈ 530 lines.
4. **Repeated image block.** New rule in `_check_links`: the draft's
   target list must equal the current list with zero or more occurrences
   removed, where each removed target occurs ≥2 times in the current L3
   and ≥1 time in the draft. Anything else rejects with the existing
   `links: …` message. Order of the kept targets is unchanged.
5. **PDFs.** Run `docs/src/build_pdf.py` for all 8 guides and commit the
   PDFs. Needs `markdown` + `xhtml2pdf` (not in the container venv yet;
   install for the build only).

Release: bump `pyproject.toml` to 1.33.1.

## Approaches considered (item 3)

| | Approach | Trade-off |
|---|---|---|
| **A (picked)** | Move `_check_*` to `fixchecks.py` | Pure functions, one concern, easy to test; item 4 lands in the new file. |
| B | Move the write side (`_atomic`, `_write_*`, `_record`, `_recheck`) | Same size cut, but more coupled to `_Target` and the apply flow. |
| C | Leave it (704 < 800 soft ceiling) | Zero risk, gap stays open. |

Items 1, 2, 4, 5 have one sensible approach each (above).

## Tests

- Report: AI-fixed section with a recheck finding prints the fix line and
  the finding; with none, prints only the fix line.
- Docling: `load_or_parse` without docling raises `KbError`; CLI exits
  without traceback.
- Links: deleting a repeated block with a duplicated image passes;
  deleting a single-occurrence image, reordering, or deleting every copy
  still rejects.
- Split: existing fix test suite passes unchanged.
