# L3 AI Structure Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With a per-repo switch on, the chat AI (Claude Code, Copilot, Cursor) proposes L3 fixes as draft files and `kb l3 fix apply` verifies each draft word by word against the PDF and the layout contract before writing it; every AI change and every direct L3 edit is gated until a human confirms.

**Architecture:** New pure modules under `src/strata_kb/l3check/`: `spans.py` (unit page spans saved at ingest), `fixrecord.py` (`_l3fix.yaml` baseline/records + gate), `lint.py` (rules R1–R8), `wordcheck.py` (word-level diff vs PDF), `fix.py` (draft loading, checks 1–5, atomic write of L3/manifest/L2/spans/l3check/record). `cli.py` stays thin: `kb l3 lint`, `kb l3 fix on|off|pages|apply`. `ingestcmd` writes spans always and the baseline only when the switch is on. `report.blocked_docs` and `kb l3 report/confirm` learn about `_l3fix.yaml`. Skills/commands for the three tools ship via `kb init`.

**Tech Stack:** Python 3.11+, pydantic, typer, stdlib `difflib`, pypdfium2 (existing), docling cache (existing), pytest.

**Spec:** `docs/superpowers/specs/2026-10-31-l3-ai-fix-design.md` §5, §6, §9, §10, §11 (Part 2). Part 1 shipped as 1.33.0 on this branch.

## Global Constraints

- No new dependency.
- No change to `SectionEntry`, `Manifest`, `index.yaml` schema, or `_l3check.yaml` schema (`FindingKind` unchanged) — wire/CI compat (spec §5).
- Switch default off. With the switch never turned on, behaviour equals 1.33.0, except `kb ingest` writing the scratch file `.kb-work/<id>/sections.json` (spec §9.2).
- Tables are never changed by a draft: same table blocks, byte for byte, same order (spec §9.4 check 1).
- No word may enter L3 without the PDF showing it in that context (spec §9.4 check 3, word level). `ANCHOR = 3`.
- The AI never confirms. Only `kb l3 confirm` (a human) clears the gate. The gate reads `_l3fix.yaml`, not the switch.
- `_l3fix.yaml` is committed in the child repo, never published (`pubgate._LOCAL_ONLY_BASENAMES`).
- Drafts and page images live under `.kb-work/<id>/`; `kb l3 fix on` adds `.kb-work/` to the repo `.gitignore`.
- A chapter file can be fixed only while every unit in it is `pending`.
- Version `1.33.0` (owner decision: Part 1 and Part 2 ship together in the next release; 1.33.0 is already in pyproject/uv.lock/CHANGELOG/test pin from Part 1 — do not bump).

## Review Focus

1. A draft byte-identical to the original (or differing only in CRLF / trailing whitespace) must apply as `unchanged`: no L3 write, no `_l3fix.yaml` entry, no new gate — Task 6 test.
2. A second fix of an already fixed unit (renamed `x1` → `4.2`, then a draft named `4.2.md`) must chain: record `was: "4.2"`, gate on the newest digest only — Task 6 test.
3. `--pdf` pointing at a different PDF than the one ingested must refuse the whole run before reading drafts — Task 6 test.
4. Turning the switch off while AI fixes are unconfirmed must leave summarize/build/publish blocked — Task 3 test.
5. A unit renamed or deleted by a direct edit of `.raw.md` + `_manifest.yaml` (bypassing apply) must block as `removed outside kb l3 fix apply`, and `kb l3 confirm --section <old-id>` must clear it — Task 3 and Task 7 tests.

    - id not in `digests` → `removed outside…`
    - entry exists and `entry.l3_sha256 == digest` → blocked `ai-fix awaiting review` unless `entry.confirmed.l3_sha256 == digest`
    - else baseline digest equals current → not blocked
    - else → `edited outside…`
  - `fixrecord.blocked_ids(kb_dir: Path, doc_id: str) -> list[tuple[str, str]]` — loads record + `report.current_digests`; `[]` when no file.

- `_run_ingest`: after the L3 check, call `fixrecord.reset_on_ingest` with `stems` = files of the re-ingested units (all files on a full ingest) and their digests; when the switch is on, echo `AI fix: on — run the kb-l3-fix skill (or /kb-l3-fix), then kb l3 report <id>`.

### Task 4: Layout contract lint (R1–R8) and `kb l3 lint`

**Files:**

**Interfaces:**
- Consumes: `spans.SpansFile/section_input` (Task 2), `detect.normalize_words`, `detect.break_findings`.
- Produces:
  - `@dataclass(frozen=True) class LintIssue`: `section: str`, `rule: str` (`"R1"`…`"R8"`), `line: int` (1-based within the unit slice), `evidence: str` (≤ 80 chars)
  - `@dataclass(frozen=True) class UnitContext`: `span: UnitSpan`, `is_fallback: bool`, `furniture: list[str]` (furniture strings of the span's pages), `pdf_pages: dict[int, str]`
  - `lint.lint_unit(unit_md: str, ctx: UnitContext) -> list[LintIssue]` (unit_md starts at its `## ` line)
  - `lint.lint_file(raw_md: str, contexts: dict[str, UnitContext]) -> list[LintIssue]` — splits on `## ` lines (`mdutils.section_map` order), runs `lint_unit` per unit plus R2 across the file.
  - `lint.lint_doc(kb_dir: Path, doc_id: str, data: SpansFile, pdf_pages, furniture: dict[int, list[str]]) -> list[LintIssue]`
  - CLI `kb l3 lint <doc-id> --pdf <pdf> [--kb-dir] [--work-dir .kb-work]` prints `§<id> <rule> line <n>: <evidence>` per issue, `L3 lint: clean` or `<n> issue(s)`; exit 1 on any. Missing `sections.json` → red `no sections.json for <id> — re-ingest` exit 1. PDF context via `lint.load_pdf_context` (Step 3); Task 6 imports it from here.
- Rules (exact):
  - R1: `ctx.is_fallback` → issue on line 1.
  - R2: an id that heads more than one unit in the file.
  - R3: heading levels inside the unit: a `#` (level 1) line, a jump of more than one level from the previous heading (`##` → `####`), a heading with no text after the marks, or a level ≥ 5.
  - R4: two prose blocks (blank-line separated, not table/heading/fence/image) with equal `normalize_words` lists of length ≥ `detect.MIN_RUN`.
  - R5: a line whose `normalize_words` equals that of a furniture string of the span's pages (non-empty).
  - R6: a line starting with `>` or `<` (after optional spaces), a `~~~` fence, or a list item indented ≥ 4 spaces deeper than the first item of its list (tabs = 4).
  - R7: an odd number of ```` ``` ```` fence lines.
  - R8: `detect.break_findings(spans.section_input(ctx.span, unit_md), ctx.pdf_pages)` non-empty → one issue per finding, evidence = its `l3` evidence.

### Task 5: Word-level check against the PDF

**Files:**
- Create: `src/strata_kb/l3check/wordcheck.py`
- Test: `tests/test_l3fix_wordcheck.py` (new)

**Interfaces:**
- Consumes: `detect.normalize_words`, `detect.strip_markdown`, `detect._page_words`.
- Produces:
  - `ANCHOR = 3`
  - `wordcheck.prose_words(md: str) -> list[str]` = `normalize_words(strip_markdown(md))` (tables included: they are identical on both sides by check 1, and they keep PDF windows contiguous).
  - `wordcheck.span_words(pdf_pages: dict[int, str], furniture: dict[int, list[str]], page: int | None, end_page: int | None) -> list[str]` — furniture-free words of pages `page..end_page` that exist in `pdf_pages`.
  - `@dataclass(frozen=True) class WordIssue`: `op: str` (`"insert" | "replace" | "delete"`), `draft: str` (the draft window, ≤ 20 words), `original: str` (the original words removed or replaced, ≤ 20 words)
  - `wordcheck.check_words(original_md: str, draft_md: str, pdf_words: list[str]) -> WordIssue | None` — first unjustified change or `None`.
  - `wordcheck.uncovered_share(md: str, pdf_words: list[str]) -> float` — share of `prose_words(md)` inside `detect._uncovered_runs(words, pdf_words)` runs; `1.0` when `pdf_words` is empty.
- Algorithm (spec §9.4 check 3; one rule covers insert, replace, delete, dedupe, furniture and moves):

```
a, b = prose_words(original_md), prose_words(draft_md)
for tag, i1, i2, j1, j2 in SequenceMatcher(None, a, b, autojunk=False).get_opcodes():
    if tag == "equal": continue
    window = b[max(0, j1 - ANCHOR) : min(len(b), j2 + ANCHOR)]
    if not window or not _contains(pdf_words, window): return WordIssue(tag, ...)
    removed = a[i1:i2]                      # delete / replace only
    if removed and _contains(pdf_words, removed) and not _contains(b, removed):
        return WordIssue(tag, ...)          # real PDF text dropped, and not a duplicate
return None
```

`_contains(haystack, needle)` = `" " + " ".join(needle) + " "` in `" " + " ".join(haystack) + " "` (normalised words never hold spaces). Empty `window` (draft emptied entirely) is a failure. The second rule closes the edge case the window rule cannot see: text removed at the very start or end of a unit has anchors on one side only. Furniture is absent from `pdf_words`, garbled words are absent from the PDF, and a removed duplicate still occurs in the draft, so those deletions pass.
