# Phase 4 — BA Agent — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase 4 — `ticketlint` engine + `kb ticket lint` CLI, the `kb_ticket_lint` MCP tool, the `ba-ticket-author` skill + standard ticket template, the new init kind `ba` (BA requirements repo), and the CI DoR gate — so a BA in the team's requirements repo runs `/ba-ticket-author` and merges only lint-PASS tickets.

**Architecture:** No engine changes. New modules `ticket.py` (template contract) and `ticketlint.py` (lint engine reusing `doctor.check_context`, `kbcontext.parse`, `resolve.resolve_refs`); a `kb ticket` Typer sub-app; a fifth MCP tool; a third `RepoKind` (`ba`) with its own minimal template set (`BA_TEMPLATES`: 4 ba-ticket-author wrappers + ticket template + CI workflow). Core four MCP tools untouched; hub/child scaffolds gain NOTHING (Devs do not draft tickets — kind `dev` + its own agent is Phase 5).

**Tech Stack:** Python 3.12, Typer, FastMCP (mcp>=1.2), pytest (`git_kb` fixture), uv.

**Spec:** `docs/superpowers/specs/2026-07-17-ba-agent-design.md` (v2)

## Global Constraints

- Core MCP tools `kb_search` / `kb_get_section` / `kb_context_new` / `kb_resolve` must not change signature or behavior — assert in tests.
- Hermetic tests: no network, no live hub, no LLM CLI (existing pattern).
- Windows dev box: tests via `uv run pytest`; lint gate `uv run ruff check <touched files>` (whole-tree ruff has known pre-existing failures elsewhere; black is NOT a project dependency).
- English headings in the ticket template are the lint contract — never localize them; changing `REQUIRED_HEADINGS` is a breaking change (minor/major only).
- Lint must handle UTF-8 Vietnamese ticket bodies and `§` on Windows consoles (`utf8io` pattern); at least one Vietnamese-body golden ticket in tests.
- Conventional commits, no attribution footer.
- Estimated total effort: ~2–2.5 dev-days across 6 tasks (T1 ≈ half day, T2–T3 ≈ half day, T4 ≈ half day, T5 ≈ half day, T6 ≈ small).

### Task 1: `ticket.py` (template contract) + `ticketlint.py` (engine) + tests

**Files:**
- Create: `src/center_kb/ticket.py`
- Create: `src/center_kb/ticketlint.py`
- Create: `src/center_kb/templates/init/ticket-template.md`
- Create: `tests/test_ticketlint.py`

**Interfaces:**
- Consumes: `doctor.Issue`, `doctor.check_context`, `kbcontext.parse/_REF_RE semantics`, `hub.HubHandle`.
- Produces: `ticket.REQUIRED_HEADINGS: tuple[str, ...]`, `ticket.STORY_RE`, `ticketlint.lint(text: str, hub: HubHandle | None) -> LintReport` where `LintReport` has `issues: list[Issue]`, `passed: bool`, `to_json() -> dict`, `render() -> str`.

- [ ] **Step 1: Write the failing tests first**

In `tests/test_ticketlint.py`, build a golden PASS ticket string (all headings, valid story line, 2 ACs with citations, both mermaid fences, kb-context block pinned via the `git_kb` fixture hub + `kbcontext.build_context_block`) and a second golden ticket with a Vietnamese body (English headings). Then one test per check from spec §5:

- missing each required heading → error naming the heading
- story line not matching `As a … I want … so that …` → error
- zero `- [ ]` items under Acceptance Criteria → error
- sequence-diagram fence missing / not `sequenceDiagram`; business-flow fence missing / not `flowchart` → error
- malformed kb-context YAML → error (message from `kbcontext.KBContextError`)
- broken ref (section id that never existed) → error; stale ref (edit the L2 after pinning) → warning
- inline citation in body absent from refs → error; pinned ref never cited in body → warning
- AC without any citation → warning
- `passed` is False iff ≥1 error; `to_json()` shape `{"pass": bool, "errors": [...], "warnings": [...]}`
- hub is None → single error "hub unreachable", no crash
- template-sync test: every heading in `ticket.REQUIRED_HEADINGS` appears exactly once in `templates/init/ticket-template.md`

Run: `uv run pytest tests/test_ticketlint.py -v` — expected: FAIL (modules don't exist).

- [ ] **Step 2: Implement `ticket.py`**

`REQUIRED_HEADINGS` = ("## Summary", "## User Story", "## Background / Business context", "## Acceptance Criteria", "## Use cases", "## Sequence diagram", "## Business flow", "## KB context", "## Definition of Ready") plus a level-1 title check (`# ` first non-empty line). `STORY_RE = re.compile(r"as an?\s+.+?i want\s+.+?so that\s+", re.I | re.S)`.

- [ ] **Step 3: Implement `ticketlint.py`**

Checks in spec §5 order; short-circuit only where meaningless to continue (no kb-context block → skip checks 6–8, still run the rest). Inline-citation regex: `(?:([A-Za-z0-9][\w.-]*):)?([A-Za-z0-9][\w.-]*)\s+§([^\s,;)\]]+)` applied outside code fences except the kb-context fence; normalize match → compare with pinned refs ignoring repo qualifier when the inline cite has none. Delegate ref resolution to `doctor.check_context(text, hub)` and map its issues through (broken=error, stale=warning). `render()` mirrors doctor output style, final line `DoR: PASS` / `DoR: FAIL`.

- [ ] **Step 4: Write `templates/init/ticket-template.md`**

Exactly the structure from spec §4 (with placeholder text and empty mermaid skeletons). Keep the kb-context block as a fenced yaml example with `<hub commit>` placeholder — the template itself must NOT pass lint (it has no real refs); the sync test compares headings only.

- [ ] **Step 5: Tests + lint**

Run: `uv run pytest tests/test_ticketlint.py -v` — ALL PASS.
Run: `uv run ruff check src/center_kb/ticket.py src/center_kb/ticketlint.py tests/test_ticketlint.py` — clean.

- [ ] **Step 6: Commit**

```bash
git add src/center_kb/ticket.py src/center_kb/ticketlint.py src/center_kb/templates/init/ticket-template.md tests/test_ticketlint.py
git commit -m "feat: ticket template contract + DoR lint engine (phase 4)"
```
