# Phase 4 — BA Agent — Kế hoạch triển khai (bản tiếng Việt)

> **Lưu ý:** Bản dịch để đọc; bản tiếng Anh cùng tên (không có `.vi`) là bản chuẩn để agent thực thi (superpowers:subagent-driven-development hoặc superpowers:executing-plans, làm từng task, tick checkbox `- [ ]`).

**Mục tiêu:** Ship Phase 4 — engine `ticketlint` + CLI `kb ticket lint`, MCP tool `kb_ticket_lint`, skill `ba-ticket-author` + ticket template chuẩn, init kind mới `ba` (repo requirement của BA), và CI DoR gate — để BA trong repo requirement của team chạy `/ba-ticket-author` và chỉ merge được ticket lint PASS.

**Kiến trúc:** Không đổi engine. Module mới `ticket.py` (hợp đồng template) và `ticketlint.py` (engine lint tái dùng `doctor.check_context`, `kbcontext.parse`, `resolve.resolve_refs`); Typer sub-app `kb ticket`; MCP tool thứ năm; `RepoKind` thứ ba (`ba`) với bộ template tối giản riêng (`BA_TEMPLATES`: 4 wrapper ba-ticket-author + ticket template + workflow CI). Bốn MCP tool lõi không đụng; scaffold hub/child KHÔNG nhận gì (Dev không soạn ticket — kind `dev` + agent riêng là việc của Phase 5).

**Tech stack:** Python 3.12, Typer, FastMCP (mcp>=1.2), pytest (fixture `git_kb`), uv.

**Spec:** `docs/superpowers/specs/2026-07-17-ba-agent-design.md` (v2; bản đọc: `...-design.vi.md`)

## Ràng buộc toàn cục

- Bốn MCP tool lõi không được đổi chữ ký/hành vi — có test assert.
- Test hermetic: không mạng, không hub thật, không LLM CLI.
- Máy dev Windows: `uv run pytest`; lint gate `uv run ruff check <file đã sửa>` (ruff toàn cây có lỗi tồn đọng ở file khác; black KHÔNG phải dependency).
- Heading tiếng Anh trong template là hợp đồng lint — không dịch; đổi `REQUIRED_HEADINGS` = breaking change (chỉ minor/major).
- Lint phải xử lý thân bài tiếng Việt UTF-8 và `§` trên console Windows (pattern `utf8io`); ít nhất một golden ticket thân tiếng Việt trong test.
- Conventional commits, không footer attribution.
- Ước lượng tổng: ~2–2.5 dev-days cho 6 task (T1 ≈ nửa ngày, T2–T3 ≈ nửa ngày, T4 ≈ nửa ngày, T5 ≈ nửa ngày, T6 ≈ nhỏ).

### Task 1: `ticket.py` (hợp đồng template) + `ticketlint.py` (engine) + test

**File:**
- Tạo: `src/center_kb/ticket.py`, `src/center_kb/ticketlint.py`, `src/center_kb/templates/init/ticket-template.md`, `tests/test_ticketlint.py`

**Interface:**
- Dùng: `doctor.Issue`, `doctor.check_context`, ngữ nghĩa `kbcontext.parse/_REF_RE`, `hub.HubHandle`.
- Cung cấp: `ticket.REQUIRED_HEADINGS`, `ticket.STORY_RE`, `ticketlint.lint(text, hub) -> LintReport` (`issues`, `passed`, `to_json()`, `render()`).

- [ ] **Bước 1: Viết test fail trước**

Dựng golden ticket PASS (đủ heading, story hợp lệ, 2 AC có citation, đủ 2 fence mermaid, kb-context pin qua hub fixture `git_kb` + `kbcontext.build_context_block`) và golden ticket thứ hai thân tiếng Việt (heading tiếng Anh). Mỗi check spec §5 một test:

- thiếu từng heading → error nêu tên heading
- story không khớp `As a … I want … so that …` → error
- không có `- [ ]` dưới Acceptance Criteria → error
- thiếu fence sequence/`sequenceDiagram`; thiếu fence flow/`flowchart` → error
- kb-context YAML hỏng → error (message từ `kbcontext.KBContextError`)
- ref broken → error; ref stale (sửa L2 sau khi pin) → warning
- cite inline không có trong refs → error; ref pin mà không cite → warning
- AC không citation → warning
- `passed` False khi và chỉ khi có ≥1 error; shape `to_json()` = `{"pass", "errors", "warnings"}`
- hub None → một error "hub unreachable", không crash
- test đồng bộ: mọi heading trong `REQUIRED_HEADINGS` xuất hiện đúng một lần trong template

Chạy `uv run pytest tests/test_ticketlint.py -v` — kỳ vọng FAIL (module chưa có).

- [ ] **Bước 2: Implement `ticket.py`** — `REQUIRED_HEADINGS` = ("## Summary", "## User Story", "## Background / Business context", "## Acceptance Criteria", "## Use cases", "## Sequence diagram", "## Business flow", "## KB context", "## Definition of Ready") + check title cấp 1 (dòng đầu `# `). `STORY_RE = re.compile(r"as an?\s+.+?i want\s+.+?so that\s+", re.I | re.S)`.

- [ ] **Bước 3: Implement `ticketlint.py`** — check theo thứ tự §5; chỉ short-circuit khi vô nghĩa (không có kb-context → bỏ 6–8, vẫn chạy phần còn lại). Regex cite inline: `(?:([A-Za-z0-9][\w.-]*):)?([A-Za-z0-9][\w.-]*)\s+§([^\s,;)\]]+)` áp ngoài code fence trừ fence kb-context; so với refs đã pin, bỏ qua repo qualifier khi cite không có. Resolve ref ủy quyền `doctor.check_context` (broken=error, stale=warning). `render()` style doctor, dòng cuối `DoR: PASS|FAIL`.

- [ ] **Bước 4: Viết `ticket-template.md`** — đúng cấu trúc spec §4, placeholder + khung mermaid rỗng; kb-context giữ placeholder `<hub commit>` — template KHÔNG pass lint (không có ref thật); test đồng bộ chỉ so heading.

- [ ] **Bước 5: Test + lint** — `uv run pytest tests/test_ticketlint.py -v` ALL PASS; ruff sạch trên file mới.

- [ ] **Bước 6: Commit** — `git commit -m "feat: ticket template contract + DoR lint engine (phase 4)"`
