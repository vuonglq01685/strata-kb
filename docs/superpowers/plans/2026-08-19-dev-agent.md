# Phase 5 — Dev Agent — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Phase 5 in two stages. **Stage A (Tasks A1–A3):** init kind `dev` + the `dev-implement-ticket` skill, so a Dev in their product repo runs `/dev-implement-ticket`, resolves the ticket's pinned kb-context, verifies `%%TODO: verify against codebase%%` placeholders against real code, and implements AC-by-AC with verbatim, cited standard values. **Stage B (Tasks B1–B5):** `kb code-ingest` — deterministic Codebase-as-Knowledge extraction into `.kb/<repo-id>-code/` (4-layer format) — plus the `kb-code.yml` CI workflow publishing it to the hub via the existing OIDC intake on every merge. Stage A is releasable alone (minor); Stage B follows as its own minor release.

**Architecture:** Stage A: no engine changes — a fourth `RepoKind` with its own `DEV_TEMPLATES` map (exact Phase 4 `ba` pattern) and four skill wrapper templates. Stage B: one new package `codeingest/` (extractor protocol + `python`/`deps`/`sqlite` extractors + orchestrator/writer) and one Typer command; `models.py`, `build.py`, `searchdb`, federation, MCP (5 tools, golden contract byte-identical), and web are all untouched — generated docs are ordinary 4-layer content.

**Tech Stack:** Python 3.12, Typer, stdlib `ast`/`sqlite3`/`tomllib`, pytest (`git_kb` fixture), uv.

**Spec:** `docs/superpowers/specs/2026-08-19-dev-agent-design.md`

## Global Constraints

- The five MCP tools must not change: `tests-gate/golden/mcp_tools.json` stays byte-identical; the regression suite (`tests-gate/regression/test_mcp_contract.py`) must stay green untouched.
- No pydantic model changes (`models.py` frozen — spec §3.3); `build.py` frozen — generated content satisfies its invariants by construction (spec §3.6).
- Hermetic tests: no network, no live hub, no LLM CLI; SQLite fixtures are generated at test time, never committed as binaries.
- Determinism (Stage B): no wall-clock timestamps (`ingested` = HEAD commit date), no unsorted dict/set iteration in emitted output — sort by (group, id) everywhere; two runs on the same tree must produce byte-identical files (tested).
- Windows dev box: tests via `uv run pytest`; lint gate `uv run ruff check <touched files>` only (whole-tree ruff has known pre-existing failures); UTF-8 via `utf8io` patterns.
- English skill/template headings; conventional commits, no attribution footer.
- Estimated effort: Stage A ≈ 1–1.5 dev-days (A1 ≈ half, A2 ≈ half, A3 small); Stage B ≈ 4–5 dev-days (B1 ≈ 2, B2 ≈ 1, B3 ≈ half–1, B4 ≈ half, B5 small).
