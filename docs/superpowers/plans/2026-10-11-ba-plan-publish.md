# BA plan on the hub — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `ba` repo publishes its lint-clean missions and DoR-passed tickets to the hub as `<repo_id>-plan` via `kb publish`. Missions and tickets carry a revision and change log, and `kb ticket stale` also reports architecture drift.

**Architecture:**
- A new deterministic `kb plan-ingest` turns `missions/` + `tickets/` into a generated doc, reusing `codeingest`'s renderer. `kb publish` in a `ba` repo regenerates it, and a `ba`-flavoured tag-triggered `kb-publish.yml` regenerates it again in CI before `kb ci-publish`.
- A new `planrev` module owns revision, change-log and parent-pin parsing for lint, `mission next` and `plan-ingest`.
- Drift reuses `resolve.resolve_refs` with a hub commit found from the `-code` manifest's history.

**Tech Stack:** Python ≥3.11, typer, pydantic, pytest (+xdist), ruff 0.15, pyright 1.1.414 (basic, `src/`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-ba-plan-publish-design.md`. Read it first; this plan argues from it.

## Global Constraints

- No new runtime or dev dependency.
- Every file write uses `encoding="utf-8", newline="\n"` (Windows CI gate).
- Old missions and tickets (no `> Revision:`, no `## Change log`, no `@ rev`) still lint PASS. New checks on absent fields emit warnings only.
- `mission.REQUIRED_MISSION_HEADINGS` and `ticket.REQUIRED_HEADINGS` stay unchanged. They are compatibility contracts.
- CI never writes into the BA repo. `.kb/<repo_id>-plan/` is gitignored and never committed.
- Story ids are never renumbered. Decision rows are never edited; they are superseded.
- Exact strings from the spec:
  - doc id `<repo_id>-plan`;
  - manifest title `<repo_id> — plan`;
  - banner `> Generated by kb plan-ingest at <short-commit> — do not edit by hand.`;
  - group `tickets` for unparented tickets;
  - triggers `kb-context`, `architecture`, `scope`, `delivery`;
  - status `SUPERSEDED`;
  - drift reason `architecture`;
  - missing baseline reason `baseline not on hub`;
  - demotion reason `parent mission rev <M> affects this story`.
- Local gate before each commit: `.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/pyright && .venv/bin/pytest -q -n auto <touched tests>`.
- Code search: use the GitNexus MCP tools (`query`, `context`, `impact`) first. Run `impact` before editing an existing symbol, and `detect_changes` before committing. Fall back to Grep only for literals.

## Review Focus

1. **CRLF or NFD input.** A mission saved with CRLF line endings, or with Vietnamese text in NFD, must produce the same `-plan` sections as its LF/NFC twin. Pinned in Task 4.
2. **`## ` inside fenced blocks.** A Mermaid or code block holding `## ` lines must not be demoted and must not open a section. Pinned in Task 4.
3. **Nothing qualifies.** Empty `missions/`, or every item skipped, means no `-plan` doc dir and no index entry. A previous one is removed so the next publish deletes it. Pinned in Task 4.
4. **Supersede cycle.** `D1 → D2 → D1` must not loop in `mission next`. Report the story `blocked` with reason `supersede cycle D1`. Pinned in Task 2.
5. **Baseline on several hub commits.** The same `-code` revision on several hub commits means the newest is used. A revision on none gives one `baseline not on hub` finding. Pinned in Task 7.

### Task 11: Intake reuses a dead `publish/<rid>` branch and opens no PR (runs after Task 7)

Owner report: on child, dev and ba repos, a publish often lands on the branch name of an old PR whose branch was deleted, and no new PR is created.

**Suspected root cause (verify before fixing; superpowers:systematic-debugging):**
- `intake.intake_publish` (`src/strata_kb/intake.py:~1609-1640`) decides `reset = dest_on_main or not gitio.rev_exists(handle.root, branch)`. It reuses the serving clone's **local** `publish/<rid>` whenever `federation/<rid>` is not on main. It never checks whether that branch still exists on the remote, or whether an open PR still uses it.
- After the old PR is closed unmerged, or merged while the clone's main is stale (`gitio.pull` failure is only a warning), the remote branch is deleted but the local branch survives. The next publish diffs against that dead branch's snapshot. If nothing changed relative to it, `_publish_in_worktree` returns `""` (`:~1777`, "nothing changed"): nothing is pushed and no PR is opened, although main does not hold the content.
- If something did change, the stale history is force-pushed under the old name. That works, but it carries commits of a closed PR.

**Files:**
- Modify: `src/strata_kb/intake.py` (`intake_publish` reuse decision)
